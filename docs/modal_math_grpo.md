# Qwen3-4B math GRPO with Modal Training Gym

This is ordinary online math RL on Lightning Weave's source task: Qwen3-4B
generates fresh responses for the math shard of `Skywork/Skywork-OR1-RL-Data`,
the repository's `math-verify` protocol grades the required `Answer:` line,
and Slime performs GRPO updates. It uses the repository's DAPO-style prompt
wrapper and answer extraction, but does not use Lightning Weave anchors,
cached targets, or Offline Direct-OPD.

The launcher now uses Modal's Training Gym for image construction, model and
dataset downloads, checkpoint conversion, Ray/NCCL startup, persistent
Volumes, detached execution, status reporting, and W&B secret injection. The
Training Gym dependency is pinned in `configs/math_grpo/train.py` to commit
`8899342e709189e2a09a6f9bdadc1e36a28dae79` so an upstream change cannot alter
an experiment silently.

The pinned Training Gym Slime image currently combines TensorBoard protobufs
generated by protobuf 6.31.1 with an older 5.29.6 runtime. The recipe upgrades
the image runtime to protobuf 7.35.1 and imports TensorBoard during the image
build, before checkpoint conversion or GPU training can begin.

Slime evaluates custom rewards on a background event-loop thread. The math
reward disables `math-verify`'s default `SIGALRM` timeouts because POSIX signals
cannot be installed from that thread; answers are extracted to one short line
before parsing, so the unbounded input that those timeouts normally protect
against is not passed to the parser.

## One-time setup

The launcher is a [uv script](https://docs.astral.sh/uv/guides/scripts/) pinned
to Python 3.12, matching Training Gym's remote image. This exact match is
required because Modal serializes some Training Gym functions. Do not use the
macOS system Python and do not install Modal globally.

Authenticate Modal and select the `alex-wa` Workspace profile:

```bash
uvx --from modal==1.5.5 modal setup
uvx --from modal==1.5.5 modal profile activate alex-wa
uvx --from modal==1.5.5 modal profile current
```

The last command must print `alex-wa`.

Create or update the existing Modal Secret. It must be named `wandb-secret`
and contain a key named `WANDB_API_KEY`:

```bash
export WANDB_API_KEY='...'
uvx --from modal==1.5.5 modal secret create --force \
  wandb-secret WANDB_API_KEY="$WANDB_API_KEY"
unset WANDB_API_KEY
```

You can instead edit the secret in the Modal dashboard, which avoids putting
the key in shell history.

The Training Gym dashboard is not required for optimization or W&B logging,
and there is no separate setup step. Training Gym makes a best-effort attempt
to deploy it because it powers Gym run state, checkpoint discovery, logs, and
the `training-gym run` CLI. A dashboard failure only prints a warning and does
not stop training. W&B remains the primary metrics view for this recipe.

## Validate, smoke test, then run

First resolve the pinned dependency and validate the full configuration without
starting a Modal app:

```bash
bash scripts/train_math_grpo.sh --dry-run
```

Then run a one-rollout smoke test. It still requests eight H100s, but samples
only 16 responses with the full run's 4,096-token response limit and waits so
any setup or runtime error is visible in the terminal:

```bash
bash scripts/train_math_grpo.sh --smoke-test --wait
```

Launch the full 100-step job only after that succeeds:

```bash
bash scripts/train_math_grpo.sh
```

The full job is detached after Training Gym finishes its download/conversion
setup and starts training. It continues if the terminal disconnects. Add
`--wait` to keep the terminal attached to status updates until completion.

The launch command prints both the Training Gym run ID and Modal app URL. Use
the run ID to inspect progress:

```bash
GYM='modal-training-gym @ git+https://github.com/modal-projects/training-gym.git@8899342e709189e2a09a6f9bdadc1e36a28dae79'
uvx --from "$GYM" training-gym run list
uvx --from "$GYM" training-gym run get RUN_ID
uvx --from "$GYM" training-gym run logs RUN_ID --follow
uvx --from "$GYM" training-gym open
```

W&B logging uses the `qwen3-4b-math-grpo` project and group by default. Change
those labels without editing code:

```bash
bash scripts/train_math_grpo.sh \
  --wandb-project my-project \
  --wandb-group qwen3-4b-math-baseline \
  --wandb-entity my-team
```

## Full-run defaults

| Setting | Value |
|---|---:|
| Model | `Qwen/Qwen3-4B` |
| Dataset | `Skywork/Skywork-OR1-RL-Data`, `data/math-00000-of-00001.parquet` |
| Modal GPU request | `H100:8` on one node |
| Training algorithm | GRPO |
| Reward | `math-verify==0.9.0`, grading the final `Answer:` line |
| Rollout/update steps | 100 |
| Prompts per rollout | 64 |
| Responses per prompt | 4 |
| Responses per rollout | 256 |
| Total sampled responses | 25,600 |
| Global batch size | 64 |
| Optimizer updates per rollout | 4 |
| Prompt / response / context limit | 1,024 / 4,096 / 5,120 tokens |
| Temperature / top-p / top-k | 1.0 / 1.0 / 16 |
| Learning rate | `1e-6`, constant |
| Adam betas / weight decay | 0.9, 0.999 / 0.01 |
| GRPO clip low / high | 0.2 / 0.28 |
| KL loss | enabled with coefficient 0.0 |
| Megatron tensor parallelism | 1; eight-way data parallelism |
| SGLang engines | 8 single-GPU engines |
| Max training tokens per GPU | 5,120 |
| SGLang static memory fraction | 0.7 |
| Save interval | every 20 rollouts |
| Model / rollout seeds | 1,234 / 42 |

The baseline's numerical settings are intentionally fixed in the recipe so the
standard run is reproducible. Run `bash scripts/train_math_grpo.sh --help` for
the operational and W&B options. Training Gym stores model caches, converted
weights, datasets, run metadata, and checkpoints in its managed Modal Volumes.

## Evaluate the saved checkpoints on AIME25

The evaluator uses the repository's `weave_aime25` protocol: the 30-row
`math-ai/aime25` test split, `Question: ...\nAnswer:` prompt, Qwen chat
template, temperature 0.6, top-p 0.95, Qwen's top-k 20, 8 responses per
problem, and `math_verify` exact-answer grading. Eight samples are a faster
estimate than the paper's Avg@64 protocol. The response cap remains the paper's
32,768 tokens. The vLLM context limit is 33,792, reserving 1,024 additional
tokens for the prompt and chat-template overhead.

List the committed checkpoints without allocating GPUs:

```bash
MODAL_ENVIRONMENT=alex-dev-2 bash scripts/eval_math_aime25.sh --list-checkpoints
```

Evaluate the base model and every committed checkpoint from the current math
run (iterations 19/39/59/79 correspond to completed rollout steps
20/40/60/80):

```bash
MODAL_ENVIRONMENT=alex-dev-2 bash scripts/eval_math_aime25.sh
```

Checkpoint export and vLLM serving still use Training Gym. Sampling, scoring,
and aggregation run in a separate 4-CPU Modal function rather than on the
launching laptop. That function has a 24-hour timeout, retries transient HTTP
requests, commits every completed problem to the
`lightning-weave-aime25-results` Modal Volume, and stops its H100 serving app
when it exits. Checkpoint export artifacts remain cached on the checkpoint
volume.

For a durable parallel launch of the untrained base model plus all four trained
checkpoints (five H100s total):

```bash
MODAL_ENVIRONMENT=alex-dev-2 bash scripts/eval_math_aime25.sh \
  --iterations 19,39,59,79 --detach
```

Once launched, neither sampling nor progress depends on the laptop remaining
online. Download current progress or completed results without allocating GPUs:

```bash
MODAL_ENVIRONMENT=alex-dev-2 bash scripts/eval_math_aime25.sh \
  --iterations 19,39,59,79 --collect
```

Collected results are written to
`results/math/aime25/vibrato-heat-e3db4b3269c6/curve.json`, with full
per-sample output in one JSON file per checkpoint.

For a cheap end-to-end smoke test:

```bash
MODAL_ENVIRONMENT=alex-dev-2 bash scripts/eval_math_aime25.sh \
  --iterations 19 --no-base --max-problems 1 --samples-per-problem 1
```

## Why this replaces the first Modal launcher

The previous `modal_qwen3_4b_math_grpo.py` duplicated Training Gym's container,
Ray, rank, checkpoint conversion, retry, and Volume logic. That made the job
sensitive to mutually incompatible Slime, Megatron, and SGLang versions. The
new launcher selects a pinned, tested Training Gym stack and expresses only the
experiment configuration. No Lightning Weave training code was changed.
